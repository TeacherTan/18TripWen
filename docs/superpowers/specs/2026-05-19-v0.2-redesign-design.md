## 2. 数据模型变更

### 2.1 `check_in_spots` schema

```sql
ALTER TABLE check_in_spots
  ADD COLUMN type           TEXT NOT NULL DEFAULT 'venue',  -- 'venue' | 'npc'
  ADD COLUMN description    TEXT NOT NULL DEFAULT '',       -- 成就列表用（解锁后展示）
  ADD COLUMN activity_intro TEXT,                            -- NPC 小游戏简介（楼层列表用）
  ADD COLUMN floor          INT,                             -- NPC 所在楼层 1-4，venue 留空
  ADD COLUMN pos_x          NUMERIC(5,2),                    -- 楼层图上 X 坐标百分比 0-100
  ADD COLUMN pos_y          NUMERIC(5,2);                    -- 楼层图上 Y 坐标百分比 0-100

ALTER TABLE check_in_spots
  ADD CONSTRAINT chk_spot_type CHECK (type IN ('venue', 'npc')),
  ADD CONSTRAINT chk_npc_has_floor CHECK (
    type = 'venue' OR (floor BETWEEN 1 AND 4 AND pos_x IS NOT NULL AND pos_y IS NOT NULL)
  );
```

`schema.sql` 同步更新（v0.2 直接重建数据库）。

## 3. 后端 API 变更

### 3.1 `/api/check-in/status`（用户端）

返回的每条 spot 增加：`type`、`description`、`floor`、`pos_x`、`pos_y`、`activity_intro`。`description` 与 `activity_intro` 仅在该 spot 已被当前用户打卡时返回真实值；未打卡时返回 `null`（前端按 `null` 渲染遮蔽态）。

> 决策：服务端遮蔽，避免客户端泄露描述内容（防"还没打卡先剧透"）。

### 3.2 `/api/admin/spots`（管理后台）

`GET` / `POST` / `PATCH` 全部接受并返回新字段。`requireAdmin` 中间件复用。

### 3.3 不变的 API

- 所有 `/api/auth/*`
- `POST /api/check-in/:spotToken`（打卡核心逻辑）
- `/api/admin/users/*`、`/api/admin/check-ins/*`

### 6.3 伪 3D DOM / CSS

```jsx
// src/components/FloorStack/FloorStack.jsx
<div className="stage">                {/* perspective: 1200px */}
  <div className="group">              {/* rotateX(55deg) rotateZ(-25deg) */}
    {FLOORS.map((f) => (
      <div className="floor" data-index={f.id} data-active={active === f.id}>
        <img src={f.image} alt={f.name} />
        {npcsOnFloor(f.id).map(n => (
          <SpotPin key={n.id} npc={n} active={highlighted === n.id} />
        ))}
      </div>
    ))}
  </div>
  <FloorPicker active={active} onChange={setActive} />
</div>
```

```css
.stage  { perspective: 1200px; perspective-origin: 50% 30%; }
.group  { transform-style: preserve-3d; transform: rotateX(55deg) rotateZ(-25deg); transition: transform .25s ease; }
.floor  { position: absolute; inset: 0; transition: transform .45s cubic-bezier(.22,.61,.36,1), opacity .45s ease; }

/* 4 套预生成 class，绕开 calc(abs()) */
.group[data-active="1"] .floor[data-index="1"] { transform: translateZ(120px) scale(1.05); opacity: 1; filter: drop-shadow(0 20px 30px rgba(0,0,0,.25)); }
.group[data-active="1"] .floor[data-index="2"] { transform: translateZ(40px)  scale(0.96); opacity: .55; }
.group[data-active="1"] .floor[data-index="3"] { transform: translateZ(-40px) scale(0.92); opacity: .35; }
.group[data-active="1"] .floor[data-index="4"] { transform: translateZ(-120px) scale(0.88); opacity: .20; }
/* 同理 active=2/3/4 各一组 */
```

切换时给 `.group` 短时加 `rotateZ(-23deg)` 再回 `-25deg` 模拟电梯启动抖动（用 React state + setTimeout(reset, 250)，简单可控）。

### 6.4 切换交互

- **点击楼层按钮**：主路径
- **手指上下滑**：在 `.stage` 上挂 `pointerdown/move/up`，垂直累计位移 > 60px 切上/下一层
- **键盘**：↑/↓ 切层（桌面调试用，可选）

### 6.5 NPC 标注（`SpotPin`）

```jsx
<button
  className="spot-pin"
  data-checked={npc.checkedAt != null}
  data-active={active}
  style={{ left: `${npc.pos_x}%`, top: `${npc.pos_y}%` }}
  onClick={() => onPick(npc.id)}
>
  <img src="/烧卖.png" alt={npc.name} />
</button>
```

- 圆形容器 `40×40`，中心 `烧卖.png` 缩略 `28×28`
- 未打卡：`opacity .5` + 灰度滤镜
- 已打卡：彩色 + 轻微 pulse 动画（沿用 `unlock-pulse` 思路，更轻量）
- 选中（被联动高亮）：黄圈 `box-shadow: 0 0 0 4px var(--state-highlight)` + scale 1.15，2s 后复位

### 6.6 联动列表

地图正下方：当前楼层所有 NPC 一条一行（头像 + 角色名 + `activity_intro`）。

- 点击列表项 → 设置 `highlightedNpcId` → 地图上对应 `SpotPin` 触发高亮动效
- 点击地图 `SpotPin` → 同时设置 `highlightedNpcId` + 在列表里 `element.scrollIntoView({ behavior: 'smooth', block: 'center' })`

### 6.8 不引入动画库的边界

所有动画用 CSS transform + transition + `@keyframes`。GPU 加速、移动端流畅。

**触发未来引入 Framer Motion 的条件**（v0.3+）：
- 要在场馆图上做相机沿路径连续运动
- 多 NPC 元素的进入/退出序列编排
- 大量 layout 切换需要 FLIP 动画

当前需求都不触发。

## 9. 风险与决策记录

| # | 风险 | 决策 |
|---|------|------|
| 1 | iOS Safari 对 3D transform 支持差异 | 用 `transform-style: preserve-3d` + `perspective` 这是标准属性，所有现代 iOS 都支持；不依赖 `backface-visibility` 等边角 |
| 2 | NPC 楼层与坐标分布暂为随机 | 设计师定稿前用固定种子的伪随机；后台可视化调整位置是 P1 必须的（避免手编 SQL） |
| 3 | 占位 icon 全是烧卖，视觉重复 | 接受。先把流程跑通，等设计师交付时一次性替换（icon 路径由 `asset_key` 映射） |
| 4 | 未引入动画库后续可能后悔 | 设了明确的"触发引入条件"（§6.8）；现在引入是 YAGNI |
| 5 | `description` 服务端遮蔽，无未解锁提示 | 接受。"探索感"优先；如需提示功能由 v0.3 单独决策 |
